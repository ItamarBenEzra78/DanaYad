תרגיל בית MRP-2 – עץ מוצר במספר תקופות

שאלה 1
t: 1, 2, 3, 4, 5, 6
V_t: 20, 40, 60, 10, y, 10
נתון: h = 1, ו-k היא עלות ההזמנה.
הכלל משתי השיטות: כל עוד העלות הממוצעת לא עלתה (ירדה או לא השתנתה) מוסיפים תקופה להזמנה. כשהיא עולה סוגרים את ההזמנה ופותחים חדשה.

סעיף 1
נתון: y = 0.
שיטת S&M, עלות ממוצעת לתקופה. הזמנה ראשונה, מתקופה 1:
1-1: C = k
1-2: C = frac{k + 40·1}{2}
1-3: C = frac{k + 40·1 + 60·2}{3}
כדי שההזמנה תכסה את תקופות 1, 2 בלבד:
frac{k + 40}{2} ≤ k
כלומר k ≥ 40
frac{k + 160}{3} > frac{k + 40}{2}
כלומר k < 200

הזמנה שנייה, מתקופה 3. היא צריכה לכסות את תקופות 3 עד 6:
3-3: C = k
3-4: C = frac{k + 10·1}{2}
3-5: C = frac{k + 10·1 + 0·2}{3}
3-6: C = frac{k + 10·1 + 0·2 + 10·3}{4}
frac{k + 10}{2} ≤ k
כלומר k ≥ 10
frac{k + 10}{3} ≤ frac{k + 10}{2}
מתקיים תמיד.
frac{k + 40}{4} ≤ frac{k + 10}{3}
כלומר k ≥ 80
לכן ב-S&M נזמין בתקופות 1, 3 עבור:
80 ≤ k < 200

שיטת LUC, עלות ממוצעת ליחידה. הזמנה ראשונה, מתקופה 1:
1-1: U = frac{k}{20}
1-2: U = frac{k + 40}{60}
1-3: U = frac{k + 160}{120}
כדי שההזמנה תכסה את תקופות 1, 2 בלבד:
frac{k + 40}{60} ≤ frac{k}{20}
כלומר k ≥ 20
frac{k + 160}{120} > frac{k + 40}{60}
כלומר k < 80

הזמנה שנייה, מתקופה 3. בתקופה 5 אין ביקוש, והעלות ליחידה לא משתנה:
3-3: U = frac{k}{60}
3-4: U = frac{k + 10}{70}
3-5: U = frac{k + 10}{70}
3-6: U = frac{k + 40}{80}
כדי שההזמנה תכסה את תקופות 3 עד 5, ובתקופה 6 תיפתח הזמנה חדשה:
frac{k + 10}{70} ≤ frac{k}{60}
כלומר k ≥ 60
frac{k + 40}{80} > frac{k + 10}{70}
כלומר k < 200
לכן ב-LUC נזמין בתקופות 1, 3, 6 עבור:
60 ≤ k < 80

הערה: שני התחומים זרים. S&M דורש k ≥ 80 ואילו LUC דורש k < 80, כלומר אין ערך k אחד שנותן את שתי התוכניות יחד.

סעיף 2
נתון: k = 90, ו-y לא ידוע.
הזמנה ראשונה, לא תלויה ב-y:
1-1: C = 90
1-2: C = frac{90 + 40}{2} = 65
1-3: C = frac{90 + 40 + 120}{3} = 83.3
העלות עלתה, כלומר ההזמנה הראשונה מכסה את תקופות 1, 2:
Q_1 = 20 + 40 = 60

הזמנה שנייה, מתקופה 3:
3-3: C = 90
3-4: C = frac{90 + 10}{2} = 50
3-5: C = frac{100 + 2y}{3}
3-6: C = frac{130 + 2y}{4}
תקופה 5 נכנסת להזמנה רק אם העלות לא עלתה:
frac{100 + 2y}{3} ≤ 50
כלומר y ≤ 25
במקרה הזה גם תקופה 6 נכנסת, כי לכל y אי-שלילי מתקיים:
frac{130 + 2y}{4} ≤ frac{100 + 2y}{3}

מקרה 1: y ≤ 25. הזמנות בתקופות 1, 3:
Q_1 = 60, Q_3 = 80 + y

מקרה 2: y > 25. ההזמנה השנייה מכסה רק את תקופות 3, 4, ובתקופה 5 נפתחת הזמנה חדשה:
5-5: C = 90
5-6: C = frac{90 + 10}{2} = 50
העלות ירדה, כלומר ההזמנה מכסה את תקופות 5, 6.
הזמנות בתקופות 1, 3, 5:
Q_1 = 60, Q_3 = 70, Q_5 = y + 10
לכן הפתרון משתנה ב-y = 25: עד 25 יש שתי הזמנות, ומעל 25 יש שלוש.

סעיף 3
עלות האחזקה היא €1 לכל יחידה שנשארת במלאי בסוף תקופה.
פריט A, לפי הווקטור Y_t:
TC = 320 + 240 + 140 = 700
פריט B, לפי הווקטור I_t:
TC = 120 + 600 + 600 = 1320
פריט C, לפי הווקטור Y_t:
TC = 300 + 300 + 40 = 640
בפריטים F, D, E לא נשאר מלאי בכלל.
לכן עלות המלאי הגבוהה ביותר היא של פריט B, והיא €1320. הסיבה היא ההזמנה לשתי תקופות בכל פעם (FP = 2).

סעיף 4
מלאי ביטחון (SS) הוא כמות נוספת של יחידות שמוחזקת במלאי כדי להקטין את הסיכון שהפריט יחסר.
ברמת התכנון לא מתכננים לספק ממנו ביקושים. אם מה שקרה בפועל לא תואם לתכנון אפשר להשתמש בו, אבל צריך להשלים אותו מוקדם ככל האפשר.
נחזיק מלאי ביטחון גבוה יותר ככל שהתהליכים אמינים פחות (חיזוי הביקוש, זמן האספקה), וככל שהרכיב נמצא ברמה נמוכה יותר בעץ המוצר.

סעיף 5
הווקטור D_t הוא הדרישות נטו: הדרישות ברוטו R_t בניכוי המלאי ביד והעול"ב, ובהתחשב במלאי הביטחון.
הווקטור V_t הוא הדרישות נטו בזמן: D_t מוזז L.T תקופות אחורה. הוא מציין את המועד המאוחר ביותר שבו צריך להוציא את ההזמנה כדי לספק את הביקוש בזמן.
הווקטור Q_t הוא פקודת הרכש או הייצור בפועל. הוא נקבע מתוך V_t לפי השיטה לקביעת גודל המנה, ואפשר להזמין בו מוקדם יותר ממה שמצוין ב-V_t.
שלושתם זהים כאשר זמן האספקה הוא אפס, ואז V_t שווה ל-D_t, וגודל המנה נקבע בשיטת LFL, ואז Q_t שווה ל-V_t.

סעיף 6
הביקוש החיצוני נרשם לפי תאריך היעד לאספקה, כלומר המועד שבו הלקוח צריך לקבל את המוצר.
מטרת המערכת היא לספק את הביקוש בדיוק בזמן. לכן מתאריך היעד היא מחשבת אחורה, לפי זמני האספקה, מתי להוציא כל פקודת הרכבה וכל פקודת רכש.
